数据分析学习总结

学习目录

核心要点

  1. 做分析，先定口径：统计什么、按什么分、和谁比较。
  2. 做透视表，先选维度和指标：地区是维度，金额是指标。
  3. 改数据，先查范围：UPDATE / DELETE 漏掉 WHERE，会影响全表。
  4. 写查询，先读懂题目：先查明细，再做汇总；保留报表需要的筛选维度。

Excel 汇总与展示

透视表四问：按什么分？统计什么？怎么汇总？占谁的比例？

1. 同比与环比

指标和谁比较增长率
同比去年同期（本期 − 去年同期）÷ 去年同期
环比紧邻的上期（本期 − 上期）÷ 上期

记住：销量上涨不等于某个人带来的效果；基期为 0 时不能直接套公式。

2. 透视表，按这 4 步做

  1. 整理数据：保留标题，用 Ctrl + T 转为超级表。
  2. 放字段：地区、渠道放行或列；金额、数量放值。
  3. 选汇总：金额求和、记录计数、最高消费取最大值。
  4. 查口径：占比看分母，新增数据后检查范围并刷新。

4. 图表怎么选

比大小：条形 / 柱形　看时间趋势：折线　看少量类别占比：饼图。

展开：电商练习的 5 类做法
  • 求和 / 最大值：地区金额、渠道订单量、渠道最大消费。
  • 交叉分析：地区 × 渠道；地区 × 性别。
  • 基准比较：与东北相比的百分比或差额。
  • 排序与分组：自定义地区顺序；日期按年、季度；年龄按区间。
  • 增长与累计：逐年增长选“上一项”；累计先明确排序。
易错：用户 ID 计数不一定是去重用户数；新增行列能否纳入，取决于数据源范围。

数据库 → 表 → 字段与记录。字段是列，记录是行。

1. SQL 的四类用途

类别做什么关键词

DML增删改记录INSERT / UPDATE / DELETE

2. 常用类型

数据类型原因
编号、数量INT / BIGINT存整数，按范围选
姓名、手机号VARCHAR(n)存文本，保留前导零

3. 用一张表记住约束

CREATE TABLE users (
  id INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(20) NOT NULL,

非空：不能是 NULL　唯一：限制重复值　默认：省略时使用预设值。

NOT NULL 不等于禁止空字符串；MySQL 的 UNIQUE 通常允许多个 NULL；自增不保证连续。

数据维护

1. 改表结构：ALTER

-- 新增字段
ALTER TABLE users ADD age INT;
-- 重命名字段，并重新写明类型和属性
ALTER TABLE users CHANGE name user_name
  VARCHAR(20) NOT NULL;
-- 删除字段
ALTER TABLE users DROP COLUMN age;

2. 改记录：增、改、删

-- 增：明确列名，值一一对应
INSERT INTO users (user_name, phone)
VALUES ('张三', '13800138001'),
       ('李四', '13800138002');
-- 改：只给开发部涨薪
UPDATE emp_study
SET emp_salary = emp_salary + 1000
WHERE emp_dept = '开发部';

-- 删：工资等于 15000 的员工
DELETE FROM emp_study
WHERE emp_salary = 15000;
执行前先查：把相同 WHERE 放进 SELECT，核对范围。以上变更示例仅用于独立练习库；调薪重复执行会重复增加。

3. 三种“删除”别混淆

命令删除什么保留结构
DELETE … WHERE …满足条件的记录是
TRUNCATE TABLE全部记录，通常重置自增是
DROP TABLE整张表否

记住：UPDATE / DELETE 不写 WHERE，会影响全表；MySQL 的 TRUNCATE 会隐式提交，不能当作可回滚的普通删除。

SQL 查询

读题找关键词：“自营”→ WHERE；“每类”→ GROUP BY；“平均”→ AVG；“前 5”→ ORDER BY + LIMIT。

1. 一条 SQL 串起查询

SELECT category_id, AVG(score) AS avg_score
FROM products
WHERE is_self = '自营'       -- 先筛选商品
GROUP BY category_id        -- 再按分类统计
HAVING AVG(score) > 9.5      -- 筛选统计结果
ORDER BY avg_score DESC     -- 从高到低
LIMIT 5;                    -- 最多取 5 组

2. 条件怎么写

需求写法
同时满足 / 任一满足AND / OR；混用时加括号
999 到 4199，含两端price BETWEEN 999 AND 4199
几个指定值之一price IN (999, 2199, 4199)
以“华为”开头 / 包含“小”name LIKE '华为%' / name LIKE '%小%'
匹配一个字符LIKE 中用 _；% 匹配零个或多个字符
没有评分 / 已有评分score IS NULL / IS NOT NULL

3. 统计记住 5 个函数

COUNT 计数　SUM 求和　AVG 平均　MAX 最大　MIN 最小。

  • COUNT(*)：统计行数；COUNT(score)：只统计非空评分。
  • WHERE：过滤原始行；HAVING：过滤分组结果。
  • 初学时，SELECT 中非聚合列都写进 GROUP BY。

4. LIMIT：先跳过，再取出

-- 按价格降序，跳过 10 行，取 5 行
SELECT id, name, price
FROM products
ORDER BY price DESC, id ASC
LIMIT 10, 5;

分页：偏移量 =（页码 − 1）× 每页条数。LIMIT 5 表示取前 5 行。

展开：自营商品中评分最高的一条
SELECT id, name, score
FROM products
WHERE is_self = '自营' AND score IS NOT NULL
ORDER BY score DESC, id ASC
LIMIT 1;

并列最高时这里只取一条；“第二条记录”也不一定是“第二高的不同价格”。

多表查询

先问两件事：用什么字段关联？哪些记录必须保留？

1. 表之间怎么关联

关系例子
一对一基本信息 ↔ 详细信息
一对多一个分类下有多个商品
多对多学生 ↔ 课程，常用中间表记录选课关系

2. JOIN：决定保留谁

连接保留范围
INNER JOIN只保留匹配成功的记录
LEFT JOIN保留左表全部记录；右表未匹配时补 NULL
RIGHT JOIN保留右表全部记录；左表未匹配时补 NULL
-- 所有分类都保留；没有商品时，数量是 0
SELECT c.id, c.name, COUNT(p.id) AS product_count
FROM category AS c
LEFT JOIN products AS p ON p.category_id = c.id
GROUP BY c.id, c.name;

易错：LEFT JOIN 后在 WHERE 限制右表字段，可能过滤掉未匹配行。若要保留所有分类、只关联自营商品，应把 p.is_self = '自营' 放进 ON。

3. 自连接：同一张表，扮演两个角色

SELECT city.title AS city, province.title AS province
FROM areas AS province
JOIN areas AS city ON city.pid = province.id
WHERE province.title = '浙江省';

4. 子查询：先算一个结果，再拿来用

-- 低于全部商品平均价
SELECT id, name, price
FROM products
WHERE price < (SELECT AVG(price) FROM products);

-- 查最高价，保留并列记录
SELECT id, name, price
FROM products
WHERE price = (SELECT MAX(price) FROM products);
展开：CROSS JOIN、UNION 与全连接

CROSS JOIN 将两边所有行组合，行数为左表行数 × 右表行数。UNION 纵向合并并去重；UNION ALL 保留重复行。MySQL 不直接支持 FULL OUTER JOIN。

-- 补充：用左连接 + 右侧未匹配行模拟全连接
SELECT p.id AS product_id, c.id AS category_id
FROM products p LEFT JOIN category c ON p.category_id = c.id
UNION ALL
SELECT p.id, c.id
FROM products p RIGHT JOIN category c ON p.category_id = c.id
WHERE p.id IS NULL;
统计前检查：一对多连接会增加结果行数。先确认每行代表什么，再求和或计数，避免金额重复累计。

MySQL 函数

函数的作用：把原始字段变成可比较、可分组、可展示的数据。

1. 常用函数，按用途记

用途函数记忆点
数字处理ROUND / FLOOR / CEIL保留小数 / 向下取整 / 向上取整
拼接与截取CONCAT / CONCAT_WS / SUBSTRSUBSTR 从 1 开始；CONCAT 遇 NULL 返回 NULL
文本整理LOWER / UPPER / REPLACE统一大小写、替换内容
统计长度CHAR_LENGTH / LENGTH字符数 / 字节数，不等于磁盘占用
日期处理DATE_ADD / DATE_SUB / DATEDIFF日期加减；DATEDIFF 只比较日期部分
提取与展示YEAR / MONTH / DAY / DATE_FORMAT提取日期部分或转成字符串
条件判断IF / IFNULL / CASE WHEN二选一 / 空值替代 / 多分支

2. 典型例子：处理文本与日期

SELECT ROUND(3.14159, 2);                   -- 3.14
SELECT FLOOR(-3.14), CEIL(-3.14);           -- -4、-3
SELECT CONCAT_WS(',', '小明', NULL, '杭州'); -- 小明,杭州
SELECT SUBSTR('abcdef', -2);               -- ef
SELECT DATE_SUB('2026-10-26', INTERVAL 1 DAY);
SELECT DATE_FORMAT('2026-10-26', '%Y-%m');   -- 2026-10

3. 多分支：从高到低判断

SELECT 学号, 科目, 成绩,
  CASE
    WHEN 成绩 IS NULL THEN '未出分'
    WHEN 成绩 >= 95 THEN 'A'
    WHEN 成绩 >= 90 THEN 'B'
    ELSE 'C'
  END AS grade
FROM score;

不能写：90 <= 成绩 < 95。SQL 应写 成绩 >= 90 AND 成绩 < 95；上面的 CASE 已用顺序排除了 ≥95。

展开：查询每个用户在 2020 年最后一次登录
SELECT user_id, MAX(time_stamp) AS last_stamp
FROM logins
WHERE time_stamp >= '2020-01-01'
  AND time_stamp < '2021-01-01'
GROUP BY user_id;

补充：半开时间区间可覆盖全年，避免漏掉 12 月 31 日的时分秒。日期筛选优先比较原始日期字段。

展开：AES 加解密的边界

函数名是 AES_ENCRYPT 与 AES_DECRYPT。密文是二进制，可用 VARBINARY 或 BLOB 保存。AES 是可逆加密；补充建议：登录密码使用专用密码哈希，不使用可解密存储。

空值和日期：IFNULL(成绩, 0) 会改变展示含义，先确认“未出分”能否按 0 处理；DATE_FORMAT 返回文本，时间运算优先保留日期类型。

指标衡量多少或多好销量、销售额、利润额、增长率

做“门店销售额 TOP10”：门店作为维度，销售额求和，按金额降序，再取前 10。

想表达什么组件

商品或门店 TOP10分组表 / 条形图

4. 仪表板的验收清单

  • 维度、指标和求和 / 计数方式正确。
  • 金额、数量和百分比的单位清楚。
  • 年月字段顺序正确，TOP10 按目标指标排序。

电商分析项目

项目主线：订单数据 → MySQL 清洗与汇总 → FineBI 仪表板。先统一口径，再追求好看的图。

1. 三层数据，各司其职

层负责什么
ODS：源数据层保存原始数据，方便追溯
DW：数据仓库层清洗、统一字段与口径，形成可复用数据
ADS / DA：应用层面向具体报表，计算指标和结果表

这是本课程的简化分层；实际项目可再细分。笔记中的分析源表为 dw_data。

2. 先确认三个统计口径

  • 订单量：已有汇总数量用 SUM(order_num)；按订单明细统计时确认是否要去重。
  • 用户数：COUNT(user_id) 是记录计数；独立用户数通常用 COUNT(DISTINCT user_id)。
  • 金额占比：分母是全国、当前地区还是东北基准，必须写清。

3. 三种可复用 SQL

-- 各渠道订单量
SELECT chann_name, SUM(order_num) AS order_count
FROM dw_data
GROUP BY chann_name;
-- 每个地区内部，男女实付金额占比
SELECT d.address, d.sex,
  ROUND(100.0 * SUM(d.real_money)
        / NULLIF(t.region_money, 0), 2) AS ratio_pct
FROM dw_data d
JOIN (
  SELECT address, SUM(real_money) AS region_money
  FROM dw_data
  GROUP BY address
) t ON d.address = t.address
GROUP BY d.address, d.sex, t.region_money;
-- MySQL 8：每年与上一年相比的金额增长率
WITH yearly AS (
  SELECT YEAR(create_time) AS yr, SUM(real_money) AS money
  FROM dw_data
  GROUP BY YEAR(create_time)
)
SELECT cur.yr,
  ROUND(100.0 * (cur.money - prev.money)
        / NULLIF(prev.money, 0), 2) AS growth_pct
FROM yearly cur
LEFT JOIN yearly prev ON prev.yr = cur.yr - 1
WHERE cur.yr BETWEEN 2017 AND 2020
ORDER BY cur.yr;

补充：NULLIF 防止分母为 0；没有上一年记录时增长率为 NULL。年度对上年度应称年度同比增长，不是月度环比。以上示例假设地区非空，空地区应在清洗时明确归类。

展开：15 个项目需求速查
需求关键做法
① 渠道订单量渠道分组 + SUM(order_num)
② 地区实付金额地区分组 + SUM(real_money)
③ 地区 × 渠道金额双维度 GROUP BY；交叉表可用条件聚合
④ 渠道最大消费MAX(consume_money)
⑤ 地区金额占比地区金额 ÷ 全部金额
⑥ 地区内男女金额占比地区性别金额 ÷ 该地区合计
⑦ 相对东北的百分比地区金额 ÷ 东北金额 × 100
⑧ 与东北的差额地区金额 − 东北金额
⑨ 年度增长率年度汇总与上一年自连接
⑩ 地区金额累计先明确地区排序，再累计
⑪ 地区按名称排序核对排序规则；编码排序不等于通用拼音规则
⑫ 自定义地区顺序与用户数ORDER BY FIELD(...)；确认是否去重用户
⑬ 年、季度金额YEAR + QUARTER 分组
⑭ 年龄段金额CASE WHEN 分段，并处理范围外 / NULL
⑮ 按性别筛选渠道金额保留 sex，按渠道与性别分组，交给 BI 筛选

4. 从 SQL 结果到仪表板

  1. 核对原数据的空值、重复值、金额和时间类型。
  2. 用 SQL 得到指标结果，校验汇总金额与占比。
  3. 需要落表时，在练习库用 CREATE TABLE … AS SELECT …，明确刷新方式。
  4. FineBI 连接结果表，更新业务包，再制作图表。
  5. 检查总额、筛选、排序和图表单位。
特别注意：按渠道汇总时若丢掉 sex 字段，FineBI 就无法继续按性别筛选；保留需要交互的维度。

这次笔记中，DAY03 的调薪和删除条件、DAY04 的 LIMIT 参数顺序已经修正。以下只列仍需留意的地方。

来源容易错的地方正确记法

来源问题处理

展开：其他基础提醒
  • DATE_FORMAT 返回字符串；日期运算优先保留原始时间类型，不能简单说“任何日期比较都不可能”。
  • LENGTH 是字符串字节数，不是表或字段真实磁盘占用。
  • Excel 普通区域刷新不会自动纳入范围外的行列；超级表也要核对扩展范围。
  • MySQL TRUNCATE 与 DELETE 的事务行为不同，不只是自增是否重置。
  • 订单建表题要求价格时，应补齐 price 字段；主键不强制叫 id。

复习题

01 · 环比上涨，能直接说明新店长做得好吗？

不能。环比只说明比上期上涨，不能直接证明因果。

02 · 地区在行、性别在列，如何看每个地区内部男女金额占比？

金额求和，值显示方式选择行汇总百分比。

03 · 为什么手机号用 VARCHAR，金额用 DECIMAL？

手机号是标识，需要保留前导零；金额需要精确的小数表示，并选择足够的位数。

04 · 查自营、价格在 999～4199 之间的商品，价格从高到低。
SELECT id, name, price
FROM products
WHERE is_self = '自营'
  AND price BETWEEN 999 AND 4199
ORDER BY price DESC, id ASC;
05 · 每页 5 条，查第 3 页，按价格降序。
SELECT id, name, price
FROM products
ORDER BY price DESC, id ASC
LIMIT 10, 5;

跳过 (3 − 1) × 5 = 10 行，再取 5 行。

06 · 分类没有商品也要显示，用哪种连接？

把 category 放在左表，LEFT JOIN products。统计商品数用 COUNT(p.id)，不要用 COUNT(*) 把空分类也计成 1。

07 · 成绩 90–94 为 B，CASE 怎么写？
CASE
  WHEN 成绩 IS NULL THEN '未出分'
  WHEN 成绩 >= 95 THEN 'A'
  WHEN 成绩 >= 90 THEN 'B'
  ELSE 'C'
END
08 · FineBI 的门店销售额 TOP10，维度和指标是什么？

维度：门店；指标：销售额求和。按销售额降序，再取前 10。核对筛选范围和金额单位。

09 · 渠道汇总结果只有 chann_name 和金额，能按性别筛选吗？

不能。需要保留 sex，按 chann_name、sex 分组，再让 FineBI 用 sex 筛选；提前聚合丢掉的维度无法凭空恢复。

                数据类型本身就是一种约束，数据约束是指在数据类型限定的基础上额外增加的要求

                主键 primary key
                  唯一标识表中的一行记录。 MySQL 建议所有表的主键字段都叫 id， 类型为int
                主键自增auto_increment
                  设置主键自增之后，新增数据时，数据库会自动把id值加1
                非空 not null
                  此字段不允许填写空值。NULL表示空
                唯一 unique
                  此字段不能重复
                默认 default
                  不填写字段对应的值会使用默认值，如果填写时以填写为准

  分层
    数据仓库架构可分为三层
      源数据层(ODS)
        直接把外部系统的数据原样搬过来，不改字段、不改内容，不对外给别人用
        就是一块临时存放接口原始数据的地方，给后面的数据加工做准备
      数据仓库层(DW)
        把 ODS 的原始数据清洗干净，去掉脏数据，得到统一、准确的数据
      数据应用层(DA或ADS层)
        给前端程序直接读的数据，按报表、专题分析的要求加工计算出来
    思考
      为什么需要有这样的三层架构,不直接存在一张表内呢
        分层是分步处理数据，原始数据、清洗明细、报表数据分开存放，互不影响，查询更快、方便排查问题
